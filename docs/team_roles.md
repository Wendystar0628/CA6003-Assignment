# 团队分工与协作

四名成员暂以 A、B、C、D 代称，确认后替换为真名。notebook 前面的分工表、各节 "Section lead" 行和 GenAI 核验行由 `notebooks/final/team.json` 生成，内容与本文件一致。

分工方式：**每节一个负责人，另一名成员评审；跨节的三件事一起做；下游发现回流修改上游。**

---

## 1. 分工

| 成员 | 角色 | 负责章节 | 评审章节 | 负责的代码 |
|---|---|---|---|---|
| **A** | 数据治理与集成 | §0 环境、§1 问题与治理、§2 数据来源 | §3、§5 | `nhanes_io`、`config`、构建工具 |
| **B** | 数据质量与准备 | §3 质量审计、§6 准备设计、§9 稳健性 | §1、§2 | `prep`（14 个准备步骤） |
| **C** | 探索分析与偏差 | §4 探索分析、§5 标签、§8 公平性 | §7、§9 | `labels`、`survey`、`fairness` |
| **D** | 建模与结论 | §7 实验、§10 综合 | §0、§4、§6、§8 | `evalkit`、`robustness` |

- **评审人：** 在冻结前检查该节的代码、数字和措辞，作者不审自己的章节。
- **工作量：** A 的章节较短，另外负责构建 notebook 和统筹视频；D 的章节少，但承担全部建模代码和最多的评审。

---

## 2. 一起做的三件事

| 事项 | 参与 | 分工 |
|---|---|---|
| **问题界定与预注册** | 全员 | A 主持讨论并整理成范围与规格；D 写统计判定规则；B、C 提出数据和标签方面的约束。锁定前全员确认 |
| **偏差缓解** | C、B、D | C 发现群体差异 → B 实现缓解步骤（重加权、WHtR）→ D 在同一折上评估 → C 写结论 |
| **结论与视频** | 全员 | 每人写自己章节的结论，D 统一成结论台账；A 核对数字并统筹视频 |

---

## 3. 反馈回路

下游的发现会退回上游修改。本项目中的三个例子：

| 从 → 到 | 发现 | 改动 |
|---|---|---|
| C → B | 探索分析发现 BMI、体重、腰围高度冗余，甘油三酯严重右偏 | B 增加血压取均值、共线性剪枝、样条三个准备步骤 |
| C → D | 30.5% 的自报患者 HbA1c 已被治疗压到阈值以下 | 训练标签改为"自报或化验"并集；D 增加"未确诊人群"作为第二个评估口径 |
| D → A、B | 试运行中含泄漏的模型 AUC 达 0.96，决策树直接用了被填补的确诊年龄 | A 在规格表里写入"只用筛查当时能拿到的变量"，B 把它实现为准备步骤 |

规则：每次冻结（范围、标签、预注册、实验、内容）都要两名成员批准。冻结后只能改措辞、降级结论或补充标明"锁定后"的分析，不能为了更好看的结果重跑。

---

## 4. 流程

1. **定范围**：全员一起界定问题和假设，A 整理成规格。
2. **并行调查**：A 接入数据并复现官方数字，B 做质量审计，C 做探索分析和标签分析，D 搭评估框架。每周同步，把发现交给需要的人。
3. **设计与实验**：B 设计准备步骤，D 跑实验和消融，C 做公平审计；评审人逐节检查。
4. **综合与视频**：D 汇总结论，全员核对；A 统筹视频录制。
