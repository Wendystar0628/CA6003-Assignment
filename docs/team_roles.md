# 团队分工与协作

四名成员以 A、B、C、D 代称。各节负责人、贡献表和个人 AI 协作说明统一写入 `notebooks/final/team.json`，再同步到最终 notebook。

分工方式：**每节一个负责人、一名不同成员评审；跨节问题共同处理；关键决定由人作出，AI 协助实现、测试和整理证据。**

| 成员 | 角色 | 负责章节 | 评审章节 | 负责的代码 |
|---|---|---|---|---|
| **A** | 数据治理、可复现与集成 | §0 环境、§1 问题与治理、§2 数据来源 | §3、§5、§10 | `nhanes_io`、`config`、`results_io`、`plots`、构建工具；变量规格与 B 共管 |

## 2. 一起做的三件事

| 事项 | 参与 | 分工 |
|---|---|---|
| **问题界定与预注册** | 全员 | 人提出 NHANES 成人糖尿病识别的选题和课程约束；A 整理范围与规格，D 写判定规则，B、C 检查数据和标签约束。AI 检查可行性并列出备选方案，成员决定各关键节点，记录理由与否决方案 |
| **准备、偏差与实验** | C、B、D，A 提供数据与规格 | C 提供分析证据 → B 转化为可开关的步骤 → D 在相同折和模型下评估 → C 解读群体变化。AI 实现算法与测试，成员决定采用、保留为敏感性分析或不采用 |
| **结论与视频** | 全员 | 每人提交“发现—证据—决定—实现—结果—需要队友处理的事项”；AI 整理交接摘要和讲稿，成员核对数字与证据强度。D 合并结论台账，A 核对来源并统筹视频 |

## 3. 反馈回路

下游的发现会退回上游修改。本项目中的三个例子：

| 从 → 到 | 发现 | 改动 |
|---|---|---|
| C → B | 血压重复测量、人体测量冗余，以及年龄、BMI 等与标签关系的非线性 | P04 聚合、P05 训练折内共线性剪枝、P13 样条；偏度另对应 P08。甘油三酯用于偏度演示，不进入主要模型 |
| C → D | 819 名自报患者中 250 名 HbA1c 低于 6.5%，其中 165 名记录用药；只用化验会漏掉这部分自报患者 | 采用“自报或化验”并集标签，同时报告 E-ALL 和未确诊筛查人群 E-SCREEN；不把所有低于阈值的病例都归因为治疗 |
| D → A、B | 试运行中含泄漏的模型 AUC 达 0.96，决策树直接用了被填补的确诊年龄 | A 在规格表里写入"只用筛查当时能拿到的变量"，B 把它实现为准备步骤 |

每次冻结由两人确认：范围 A+B、标签 C+A、预注册 D+A、实验 D+B、内容 A+D。冻结后只改实现错误或措辞；新增分析须标明"锁定后"，不替换主分析。

---

## 4. 流程

1. **定范围**：全员提出问题和约束，A 整理规格；AI 检查可行性，关键选择由人决定。
2. **并行调查**：A 接入数据并复现官方数字，B 做质量审计，C 做探索分析和标签分析，D 搭评估框架。每周同步，把发现交给需要的人。
3. **设计与实验**：B 设计准备步骤，D 跑实验和消融，C 做公平审计；先检查模块与数据边界，再跑 FAST，最后采用 FINAL 统计设置，评审人逐节核对。
4. **综合与视频**：各人提交结论，D 合并、A 核对；对不确定或恶化的结果如实解释，全员确认个人贡献和 AI 使用说明。
